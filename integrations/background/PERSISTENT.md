# Persistent SSH background tasks

Native background-task releases advertise a runtime bundle through `sydney-kit:bg-hook:v1` with `includePersistentRuntime: true`. Sydney pins the resolved SSH route and working directory when discovering a provider. Each request opens and closes its own authenticated route; commands are never replayed after transport failures. Reconnect interactively if authentication needs a password or key passphrase.

The remote host must already have Node 22 or newer. Sydney does not install Node. Runtime assets are validated against their canonical SHA256 and installed under `~/.pi/background-tasks-runtime/<digest>` using private permissions and atomic directory publication. The supervisor's stable service root is `~/.pi/background-tasks-remote`. Runtime installation alone does not submit a task.

The historical install.mjs entry point is now a read-only native source compatibility check. Releases without the native execution provider contract and readiness hook must be upgraded; source patching and manifest recording are no longer supported. Native releases without the persistence capability retain the connection-bound spawn compatibility behavior.

The persistent API accepts an optional `ownerSession` on `get(id, ownerSession?)`, `list(cwd, ownerSession?)`, `cancel(id, ownerSession?)`, and `logs(id, offset, maxBytes, ownerSession?)`; `start` takes it in the request. Supplied selectors must be nonempty strings and are forwarded unchanged. Scoped operations require `ensure.sessionOwnership === 1`, fail explicitly against older daemons, and never restart or kill a daemon to obtain support. Sydney also checks returned task ownership, including every list record and the start response. Callers omitting the selector retain legacy behavior. A resumed Pi session uses the same owner identifier; different sessions sharing a directory remain isolated, and scoped lists omit unowned historical tasks. Credentials remain confined to authenticated connections and are not persisted in task ownership metadata.

Verification: `SYDNEY_BG_ROOT=/path/to/pi-background-tasks node scripts/test.mjs ssh-persistent` runs stub checks and the actual bootstrap/bridge runtime in an isolated local temporary home. These tests do not connect to SSH. Live reconnect, daemon restart and runtime deployment should be exercised in an explicitly authorized test environment before relying on production task recovery.

SSH adapter diagnostics identify bootstrap, ensure, or the requested method. Success requires a verified zero exit status (including ssh2 exit events when close has no arguments) and a valid JSON envelope. Nonzero exits, signals, missing status, empty/malformed responses, stream failures and deadlines fail without replay. Diagnostics retain a sanitized last 8 KiB of stderr; total stdout plus stderr remains capped at 2 MiB. UTF-8 stdout is decoded across chunks. Successful commands may emit stderr warnings. Diagnostics never dump stdout or the submitted command, input, credentials, or runtime bundle.
